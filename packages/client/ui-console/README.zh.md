# @deepseek-ai/dsh-client-ui-console

[English](README.md) | 中文

## 概述

`@deepseek-ai/dsh-client-ui-console` 是 dsh web GUI 的浏览器控制台工作台。一个侧栏底部操作打开全屏三列弹窗：会话状态、任务统计、主机指标、渲染选中会话对话的限定范围时间线及其指令输入框、占位知识库与智能问答。会话状态与动词来自 `ctx.sessions`、`ctx.workspaces` 与 `sessionStats` 投影；主机指标来自转发的 `host/metrics` 事件，对话由该会话的事件流折叠而来，未限定范围的行则来自转发的 `api-session/*` 事件加上一次性的列表回填。用它即可在不离开 GUI 的情况下观察并操控会话。

## 理解实现

<details>
<summary>实现内部 —— 点击展开</summary>

弹窗是自定义的 `role="dialog"` 面板，而非盒式原始 `Modal`，以三列排布：

- **会话状态** —— 统计/网格视图切换。统计视图计数总数、运行中、等待输入、已完成与已归档；网格视图为每个会话铺一块状态色方块（绿色运行中、琥珀等待、红色规划/等待输入、品牌蓝可用、灰色已归档），带当前/选中描边与右键菜单（打开、重命名、Fork、归档）。左键点击设置控制台的作用域 —— 任务统计、时间线与指令输入框共同跟随的那一个会话 —— 卡标题栏的「全部会话」pill 清除它。
- **任务统计** —— 作用域行（整个列表或选中会话）加来自 `sessionStats` 投影的运行中、轮数、步骤数、LLM 耗时与工具耗时计数。还按操作者的价格表为作用域内会话的 token 显示费用。
- **系统状态** —— 来自转发 `host/metrics` 事件的 CPU / 内存 / GPU 环形仪表。
- **时间线** —— 选中会话自身的对话；未选中任何会话时为跨会话的活动列表。限定范围时，每条操作者消息渲染为右对齐气泡，每条助手回复渲染为左对齐文本，其下只有一行元数据，载有该回复自身的时间戳、该回复自身事件上报用量时的 token 总数，以及它所属轮次的费用；apply 闭包订阅该会话的事件流与该会话的 `sessionStats` 投影（逐轮路由桶）并发布折叠后的消息，因此卡片自身不持有订阅。只有来源为操作者的持久 `user/message` 事件与 `assistant/message` 回复会被渲染；已限定范围但已加载窗口内两者皆无的会话显示空提示。未限定范围时，它为每条转发的 `api-session/status` 与 `api-session/activity` 事件列出一行粗略记录，并为客户端已有的每个会话列出一行回填的 `history`，按更新时间从旧到新排列，从而最新的会话渲染在最上方；该回填只运行一次，即工作台首次在空时间线上打开时。默认的「活动」视图渲染全部行，仅看状态行的「状态」视图是一个切换项，这样的行折叠时为简短的会话头部，并始终提供展开开关以显示该会话的对外标题。卡片底部的指令输入框在两种视图下都向选中会话发送。
- **知识库** —— 来源列表，当前渲染空/占位状态（尚无后端 seam）。
- **智能问答** —— 通过 `ctx.remote.llm.chat` 流式完成一次性补全。

每张卡在标题行都有折叠开关，把卡片主体收起到仅剩标题栏；顶部的列布局切换（均衡 / 聚焦 / 紧凑）在宽屏下改变网格列比例。在低分辨率屏幕上网格按响应式重排（三列 → 二加一 → 单列堆叠），不受所选预设影响。

待处理交互通过 `ctx.uiSession.pendingInteractions` 的网格相位着色呈现；会话动词（打开、重命名、Fork、归档、新建、预设选择、发送指令）经由 `ctx.sessions`、`ctx.workspaces` 与 `ctx.remote.agentPresets` 面。一个「新建会话」弹窗收集工作区、可选的代理预设与首条指令。

### 费用核算

费用项按 `console-pricing` settings namespace 计价，采纳由 `dsh-client-ui-primitives` 的 `PriceTablePolicy` 负责，它在 Host 每接受一个 section 时采纳：该 namespace 在插件挂载之后才应答，因此价格表无论何时到达都能送达卡片，之后的修改也会重新计价。算术由同一个包的 `totalCost` 负责，它按每个时段自己的四项 token 计数计费 —— 缓存读取按该行的缓存命中价、未缓存输入与缓存写入按缓存未命中价、输出按输出价 —— 因为 `sessionStats` 投影已根据上报事件自身的时间与该事件的低谷窗口判定其所属时段。卡片不再重新判定时段，也绝不用计费输入减去缓存部分来反推未命中数。

价格行以 `(baseUrl, provider, model)` 为键，而上报的 token 桶只带 `provider` 与 `model`。因此只有当恰好一行命中该组合时才计价：没有命中行即报为未定价，多行仅接口地址不同则报为价格不唯一 —— 因为桶并未指明是哪个接口，任何一个接口的价格都不能拿来计费。两者都使该项不给出数字，而不是按 0 或按猜测计费。

限定范围的时间线把同一套规则用在更窄的集合上：来自该会话 `sessionStats.turnRoutes` 的、每条回复自身轮次的桶，只挂在关闭该轮次的那一条回复上 —— 即已加载窗口为该轮次保留的最后一条带文本的回复。因此跨多个步骤的一个轮次只会被计一次费，记在结束它的那条回复上，而不是每条回复各计一次；而投影从未上报路由的轮次则完全不显示费用。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与延后工作

- **智能问答需要已配置的模型** —— 面板从 `console-bridge` 设置命名空间读取模型覆盖（`smartQaModel`，形如 `provider/model`）。未设置时保持禁用；没有客户端模型目录 Remote 可回退。
- **单个 token 桶不标注接口** —— 费用项对作用域内的会话精确计价，但若价格表把同一模型分列在两个接口下，而桶又不带接口，该路由会报为价格不唯一，而不是按其中一个计价。
- **未限定范围的时间线是粗略的活动镜像** —— 未限定任何会话时，它渲染转发的 `api-session/status` 与 `api-session/activity` 行，加上每个已知会话一行回填的 `history`，而非会话事件流。这些行是转发事件与列表快照，因此回填不会重复：它只运行一次，取自那一刻客户端持有的列表。
- **限定范围的时间线只渲染已加载的事件窗口** —— 对话由会话自己的事件窗口折叠而来，而 Session Controller 只向该窗口填入部分尾部以及它已取回的更早分页；卡片既不抓取也不分页，因此长会话显示的是该窗口持有的消息，而非全部。只有持久的事件来源为操作者的 `user/message` 事件与 `assistant/message` 回复带有可渲染文本：注入的上下文、仅客户端存在的流式行，以及未提交任何对外消息的尝试都被略过。助手元数据行承载该回复自身的时间戳、该事件上报用量时该回复自身的 token 总数，以及关闭该轮次的那条回复上的该轮次费用；事件未上报用量的回复不显示用量 chip，投影从未上报路由桶的轮次不显示费用，未上报的缓存桶按 0 计。卡片不显示逐回复用时，因为事件窗口并不携带属于单条回复的计时记录 —— 它只持有 `step/start` 与 `assistant/message` 的时间戳，二者之差是 `sessionStats` 投影作为会话级数字持有的模型耗时。
- **知识库没有后端 seam** —— 卡片渲染空/占位状态，并导出行类型供未来来源填充。
- **待处理交互是监控提示** —— 控制台以会话网格方块颜色标识待处理的提问或计划审阅，但不在内联回答；回答属于对话编辑器。
